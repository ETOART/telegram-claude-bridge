# tg_claude_bot

Мост между Telegram и локальным Claude Code. Сообщение из чата передаётся в процесс `claude -p`, ответ возвращается в тот же чат.

Процесс не завершается после ответа: он остаётся запущенным и читает stdin. Инициализация (запуск Node, чтение конфигов, подключение к MCP-серверам) занимает 3–10 секунд и выполняется один раз при старте процесса. Последующие сообщения идут в уже запущенный процесс, поэтому время ответа состоит только из генерации.

`session_id` сохраняется в SQLite, поэтому перезапуск скрипта или перезагрузка машины не прерывают диалог: сессия восстанавливается через `--resume`.

---

## Установка

```bash
pip install -r requirements.txt
```

Токен получить у [@BotFather](https://t.me/BotFather) командой `/newbot` и вписать в `.env`:

```bash
cp .env.example .env
```

```bash
python tg_claude_bot.py
```

Требуется, чтобы `claude` был установлен и авторизован (проверяется запуском `claude` в терминале).

Настройки лежат в `.env`, который читается рядом со скриптом — из какого каталога запускать, неважно. Переменные окружения приоритетнее файла, поэтому `TELEGRAM_BOT_TOKEN=... python tg_claude_bot.py` и `docker run --env-file` продолжают работать как переопределение. Полный список переменных с дефолтами — в [`.env.example`](.env.example).

По умолчанию бот отвечает всем, а сессии расходуют квоту подписки Claude Code. Ограничить доступ можно через `ALLOWED_USERS` — см. [Доступ](#доступ).

## Архитектура

```
Telegram (long polling)
   ↓
Supervisor — семафор на MAX_CONCURRENT_TURNS одновременных генераций
   ↓
ChatActor[chat_id] — один процесс claude -p на чат
   ↓
stdin:  {"type":"user","message":{...}}   JSONL, одна строка на сообщение
stdout: system/init → assistant → result  JSONL события
   ↓
SQLite: chat_id → session_id | model | system_prompt | ts
```

**Long polling.** Скрипт сам запрашивает обновления у Telegram через `getUpdates`. Входящие соединения не требуются: белый IP, проброс портов, TLS-сертификат и туннель не нужны, работает за NAT.

**Дебаунс.** Сообщение не передаётся в процесс сразу — скрипт ждёт `DEBOUNCE_S` (1.2 с) на случай, если пользователь допишет продолжение. Несколько сообщений подряд объединяются в один запрос.

**Очередь сообщений.** Сообщения, пришедшие во время генерации, накапливаются в списке и передаются в процесс после события `result`. Второй процесс на тот же чат не запускается.

**Завершение по простою.** Если в чате не было сообщений дольше `IDLE_TIMEOUT_S` (15 мин), процесс завершается. `session_id` остаётся в базе; следующее сообщение запускает процесс с `--resume`, если пауза меньше `RESUME_MAX_AGE_S` (2 ч).

**Изоляция чатов.** Ключ — `chat_id`. Каждый чат и каждая группа получают отдельный процесс, отдельную сессию и отдельные настройки.

**Потоковая выдача.** Процесс запускается с `--include-partial-messages`, дельты текста приходят событиями `content_block_delta`. Ответ отправляется одним сообщением и дописывается через `editMessageText` не чаще одной правки в `EDIT_INTERVAL_S` (1.1 с) — Telegram отдаёт 429 примерно при одной правке в секунду. При получении 429 интервал увеличивается в 1.5 раза, до 5 секунд.

Пока текст не начал поступать, в сообщении отображается текущий инструмент (`⚙️ Read…`) — из событий `content_block_start` с блоком `tool_use`. Индикатор `typing` в этом режиме не используется.

При превышении лимита сообщения (3800 символов) текущее сообщение закрывается и продолжение отправляется новым. По событию `result` итоговый текст перезаписывает накопленные дельты: `result` авторитетнее.

Поддержка флага проверяется при старте вызовом `claude --help`. Если флага нет, стриминг отключается автоматически и ответы приходят целиком. Принудительно отключается через `STREAMING=0`.

## Команды

| Команда | Действие |
|---|---|
| `/context` (`/ctx`) | Модель, системный промпт, размер контекста, число ходов, состояние процесса, `session_id` |
| `/system` | Задать системный промпт следующим сообщением. `/system <текст>` — сразу, `/system show` — вывести, `/system off` — снять |
| `/compact` | Сжать разговор в конспект и начать новую сессию |
| `/clear` (`/reset`, `/new`) | Завершить процесс и удалить привязку к сессии. Модель и системный промпт сохраняются |
| `/model` | Без аргумента — вывести текущую. `/model sonnet` — сменить |
| `/cd` (`/dir`, `/project`) | Без аргумента — вывести текущий рабочий каталог. `/cd <путь>` — сменить |
| `/start`, `/help` | Вывести `chat_id` и список команд |

Остальные строки, начинающиеся с `/`, отклоняются с подсказкой. Слэш-команды Claude Code (`/cost`, `/resume`, `/vim` и прочие) в режиме `-p` не работают — их обрабатывает интерактивный REPL, который в этом режиме не запускается. Без отклонения они передавались бы в модель как обычный текст.

### Системный промпт

`/system` без аргумента включает ожидание: следующее сообщение сохраняется как системный промпт. Окно ожидания — 5 минут, после чего режим отменяется и сообщение обрабатывается обычным образом.

Промпт хранится в SQLite отдельно для каждого чата и передаётся флагом `--append-system-prompt` при каждом запуске процесса. Следствия:

- сохраняется при `/clear`, `/compact`, `/model` и перезапуске скрипта;
- не занимает место в контекстном окне диалога;
- применяется только при следующем запуске процесса, поэтому установка завершает текущий процесс. `session_id` не удаляется, контекст восстанавливается через `--resume`.

Значение `CLAUDE_SYSTEM_APPEND` не заменяется, а объединяется с пользовательским промптом через пустую строку: сначала базовое, затем пользовательское. Чтобы убрать базовое, задайте `CLAUDE_SYSTEM_APPEND=""`.

### Модель

Значение по умолчанию — `sonnet`, задаётся через `CLAUDE_MODEL`. Без явного указания Claude Code выбирает модель сам.

Выбор хранится отдельно для каждого чата и сохраняется при `/clear`, `/compact` и перезапуске скрипта. Принимаются `opus`, `sonnet`, `haiku` и полные имена вида `claude-sonnet-4-6`.

`--model` — флаг запуска процесса, изменить его у работающего процесса нельзя. Поэтому смена модели завершает процесс и удаляет привязку к сессии: контекст теряется.

### Доступ

`ALLOWED_USERS` — список user_id через запятую:

```env
ALLOWED_USERS=622492578,166090940
```

Проверка идёт по пользователю и действует в любом чате: добавление бота в группу само по себе не даёт доступа её участникам, каждый проверяется отдельно. Она выполняется раньше всего остального, поэтому посторонний не поднимет процесс и не потратит квоту.

На отклонённое сообщение приходит короткий отказ, реплаем на само сообщение — в группе иначе непонятно, что именно проигнорировано. В отказе есть `user_id` отправителя, чтобы было что передать владельцу.

Одному и тому же человеку в одном чате повторный отказ приходит не чаще `DENY_NOTICE_COOLDOWN_S` (10 минут), дальнейшие сообщения отбрасываются молча. Без этого группа с выключенным privacy mode получала бы отказ на каждое сообщение каждого постороннего. Пауза считается по паре «чат + человек», поэтому второй участник получит свой ответ. `DENY_NOTICE_COOLDOWN_S=0` — отвечать всегда.

Свой `user_id` можно узнать командой `/start`. Нечисловые значения пропускаются с предупреждением при старте — иначе опечатка тихо заперла бы вас снаружи.

Пустой список оставляет бота открытым для всех.

### Рабочий каталог

У каждого чата свой каталог: он хранится в SQLite и переживает `/clear`, `/compact` и перезапуск скрипта. Чаты, где `/cd` не вызывали, работают в `CLAUDE_WORKDIR`.

Относительный путь считается от `PROJECT_BASE_DIR`, `~` разворачивается в домашний каталог, абсолютный путь берётся как есть. Каталог должен существовать.

Смена всегда рвёт сессию: `--resume` ищет её в том каталоге, где она была создана, и в новом месте не находит.

От каталога зависит, что видит Claude Code: в его системный промпт подставляются рабочий каталог и состояние git, поэтому агент представляется по тому проекту, на который направлен.

`PROJECT_STRICT=1` запирает `/cd` внутри `PROJECT_BASE_DIR`. По умолчанию выключено. Фильтра по `chat_id` нет, так что каталог сможет назначить любой, кто нашёл бота, а у агента есть инструменты для файлов и терминала — режим ограничивает досягаемость.

### Контекст и `/compact`

В режиме `-p` нет автоматического сжатия контекста. При превышении контекстного окна запрос завершится ошибкой. Скрипт выводит предупреждение при заполнении на `CONTEXT_WARN_RATIO` (70%), однократно за сессию.

`/compact` выполняет четыре шага:

1. Отправляет в текущую сессию служебный запрос: сжать разговор в конспект (решения, факты, текущая задача, открытые вопросы).
2. Получает ответ и не отправляет его в чат.
3. Завершает процесс и удаляет привязку к сессии.
4. Сохраняет конспект и добавляет его к следующему сообщению пользователя.

Расход — один дополнительный запрос к модели. Отдельный запрос на передачу конспекта не тратится: он идёт вместе со следующим сообщением. `/context` показывает, что конспект сохранён и ожидает отправки.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | Обязательна. Токен от BotFather |
| `ALLOWED_USERS` | пусто | Список user_id через запятую, кому можно пользоваться ботом. Пусто — можно всем |
| `DENY_NOTICE_COOLDOWN_S` | `600` | Пауза перед повторным отказом тому же человеку в том же чате. `0` — отвечать всегда |
| `CLAUDE_BIN` | `claude` | Путь к исполняемому файлу, если его нет в PATH |
| `CLAUDE_MODEL` | `sonnet` | Модель для новых чатов |
| `CLAUDE_WORKDIR` | текущий каталог | Каталог по умолчанию для чатов, где не вызывали `/cd`. `--resume` привязан к пути: при смене каталога сохранённые сессии не находятся |
| `PROJECT_BASE_DIR` | `CLAUDE_WORKDIR` | База для относительных путей в `/cd` |
| `PROJECT_STRICT` | `0` | `1` запирает `/cd` внутри `PROJECT_BASE_DIR` |
| `CLAUDE_EXTRA_ARGS` | пусто | Дополнительные флаги, например `--mcp-config ./mcp.json` |
| `CLAUDE_SYSTEM_APPEND` | инструкция по форматированию для Telegram | Базовая часть системного промпта |
| `STATE_DB` | `state.db` | Файл SQLite с настройками и привязкой чатов к сессиям |
| `RESUME_MAX_AGE_S` | `7200` | Максимальный возраст сессии для `--resume`. Старше — новая сессия |
| `CONTEXT_WINDOW` | `200000` | Размер контекстного окна модели для `/context` |
| `CONTEXT_WARN_RATIO` | `0.7` | Доля заполнения, при которой выводится предупреждение |
| `STREAMING` | `1` | Потоковая выдача ответа. `0` — отправлять целиком |
| `EDIT_INTERVAL_S` | `1.1` | Минимальный интервал между правками сообщения |
| `MAX_CONCURRENT_TURNS` | `2` | Число одновременных генераций по всем чатам |
| `DEBOUNCE_S` | `1.2` | Пауза перед передачей накопленных сообщений в процесс |
| `IDLE_TIMEOUT_S` | `900` | Время простоя до завершения процесса |
| `TURN_TIMEOUT_S` | `180` | Максимальная длительность одного запроса |
| `LOG_LEVEL` | `INFO` | `DEBUG` выводит stderr процесса `claude` и события `usage` |

## Работа в группах

**Privacy mode.** По умолчанию BotFather ограничивает боту доступ к сообщениям в группах: приходят только сообщения, начинающиеся с `/`, и сообщения с упоминанием бота. Отключается командой `/setprivacy` в BotFather. При отключении каждое сообщение в группе запускает запрос к модели.

**Имена отправителей.** В непубличных чатах перед текстом подставляется префикс `[Имя]:`. Описание этого формата включено в базовый системный промпт.

## Диагностика

**Процесс завершается сразу после запуска.** Вероятная причина — несовместимые флаги, их набор меняется между версиями Claude Code:

```bash
claude --help | grep -i "input-format\|output-format\|append-system\|resume\|model"
```

Наиболее вероятный источник проблемы — `--append-system-prompt`. Отключается пустым значением:

```bash
export CLAUDE_SYSTEM_APPEND=""
```

**Просмотр stderr процесса `claude`:**

```bash
LOG_LEVEL=DEBUG python tg_claude_bot.py
```

В том же режиме выводятся события `result` целиком. По ним следует проверить, из каких полей на установленной версии собирается `usage`.

**`/context` выводит «нет данных».** Поля `usage` в событии `result` расположены иначе, чем ожидает парсер. Исправляется в функции `_absorb_usage()`.

**Ответ «Сбой сессии» на каждое сообщение.** Проверить авторизацию `claude` запуском в терминале. После трёх последовательных сбоев чат отключается на 10 минут.

**Ответ дёргается или обрывается при стриминге.** Увеличить `EDIT_INTERVAL_S` до 2–3 секунд. Полностью отключить — `STREAMING=0`.

**Windows.** Буферизация пайпов stdin/stdout отличается от Unix. При некорректной работе запускать из WSL2.

## Расход ресурсов

Денежных списаний нет: `claude -p` использует авторизацию по подписке, а не API-ключ. Расходуется квота подписки Claude Code, общая с интерактивными сессиями. Значения `MAX_CONCURRENT_TURNS`, `IDLE_TIMEOUT_S` и `DEBOUNCE_S` подобраны так, чтобы ограничить этот расход.

Запущенный процесс без активности запросов к модели не выполняет и квоту не расходует. Расход создают запуски процессов и увеличение контекста: каждый запрос отправляет всю историю сессии заново.

## Ограничения

**Требуется работающая машина.** При выключении или переходе в сон бот останавливается. Для непрерывной работы нужен сервер; авторизация в этом случае — через `CLAUDE_CODE_OAUTH_TOKEN` в окружении (получается командой `claude setup-token`). Код изменений не требует.

**Обрабатывается только текст.** Изображения, голосовые сообщения и документы игнорируются.

**Не проработана работа с большим числом чатов.** См. TODO в начале файла: каждый активный чат держит отдельный процесс, вытеснения неактивных нет. При 3–5 чатах работает штатно, при большем числе требуется ограничение числа одновременно запущенных процессов и обработка перегрузки.
